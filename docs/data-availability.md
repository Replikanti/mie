# Data availability

Which raw data exists for the BTCUSDT USDⓈ-M perpetual, from when, at what
resolution, and which features can be computed for which period. Sources:
live capture (`mie ingest`, source `binance-um`, ADR-032) and the public
archive backfill (`mie archive-import`, source `binance-archive`, ADR-034).

**Gaps** come from the acceptance run of #12 (`mie archive-verify` lists
trade-id breaks and holes over 60 s per stream), window 2025-10-01 …
2026-09-30. The archive bucket listing is stale, so availability was
checked per file (ADR-034): all 9 daily streams for each of the 365 days
and the 12 monthly `fundingRate` files were published, **0 missing**
([results](https://github.com/Replikanti/mie/issues/12#issuecomment-6032650398)).

The **hold-out year** 2024-10-01 … 2025-09-30 (`aggTrades` and `metrics`
only, #124) was probed the same way: 730 of 730 files published, 0 missing
([results](https://github.com/Replikanti/mie/issues/22#issuecomment-6135775324)).

## Live-only data

| Data | Raw stream (source `binance-um`) | Resolution | From | Normalized to |
|---|---|---|---|---|
| Aggregate trades | `aggTrade` | per aggregate | start of live capture (#9) | `Trade` |
| Mark and index price, indicative funding | `markPrice` | 1 s | start of live capture | `MarkPrice` |
| Liquidation snapshots | `forceOrder` | ≤ 1/s per symbol (throttled lower bound) | start of live capture | `Liquidation` |
| Closed 1m klines | `kline_1m` | 1 min | start of live capture | `Kline` |
| Open interest | `openInterest` | 10 s poll | start of live capture | `OpenInterest`, `resolution_ms` 10 000 |
| Order book (diff depth + snapshots) | `depth`, `depthSnapshot` | diffs per 100 ms batch; `limit=1000` snapshots on every resync and a checkpoint every 60 s (ADR-038) | start of live depth capture (#10, first soak 2026-10-08) | `BookUpdate`, `BookSnapshot` |

Live aggregates can omit trades without an id break (2026-10-08 12:50–15:43 UTC: 465 trades, 43.250 BTC, while the archive is complete), and `mie capture-report` check 7 reports such losses per block of minutes (ADR-048).

## Features by period

| Feature family | Inputs | Computable from archive (window) | Computable from live | Notes |
|---|---|---|---|---|
| Event-time bars `bars.time.*` (1m … 1d) and ATR / ATR percentile (#16) | trades | yes, from aggTrades | yes | Bars come from trades only; klines are a cross-check (ADR-031). Archive bars include the trades the aggTrades archive omits where `trades` is imported (the fold, ADR-050) |
| Delta, CVD, volume at price | trades with aggressor | yes | yes | Aggressor from `is_buyer_maker` / `m` (ADR-023) |
| OI level, ΔOI, OI velocity (#19): `derivatives.oi.sample@1` (source resolution), `derivatives.oi.5m@1` (UTC 5-minute grid) | open interest | yes, 5 min | yes, 10 s | `resolution_ms` per value tells them apart; the native step never crosses resolutions, the grid is computable from both sources (ADR-042); archive values lag up to one interval |
| Funding settlements: `derivatives.funding.settled@1` | funding rate | yes | no settlement event; the indicative rate arrives with `MarkPrice` | Live settlements come from the archive once published (next day) |
| Indicative funding, mark/index price, basis, time to next funding: `derivatives.mark@1` | mark price | **no** | yes | Mark/index price klines are not imported; stays warming up in archive replays |
| Liquidation windows by side: `derivatives.liq.window.<5m\|15m\|1h>@1` | liquidations | **no** | yes | Lower bound only; warming up until the first liquidations-stream event, so archive zeros never read as a quiet market (ADR-042) |
| Order-book liquidity state (#18): `book.l2@1` (the L2 book), `book.depth@1` (depth and imbalance within 1, 2 and 5 bps), `book.clusters@1` (largest levels within 5 bps), `book.liquidity.window.<5m\|15m\|1h>@1` (liquidity added, cancelled and filled) | order book, trades | **no** | **from the start of live depth capture (#10) only** | Live only (ADR-043): every `book.*` value stays warming up in archive replays. bookDepth bands (raw, from 2023-01-01) are too coarse to substitute |
| Location (#23, ADR-044): `location.vwap.utc_day@1` (UTC-day VWAP), `location.levels@2` (level registry with score components and zone events, over the prior-day and 7-day composite profiles; `@1`, over the 5-day composite, stays selectable), `location.auction.prior_day@1` (auction state against the prior day's value) | trades; the profile, structure and book features | yes, except the cluster levels | yes | The VWAP, the profile and structure levels and the auction state are computable from aggTrades over the whole window; the auction state from the first complete prior day on. Liquidity-cluster levels come from `book.clusters@1` and are live only (ADR-043); archive registries hold none |
| Order-flow divergences (#22, ADR-051): `candidate.divergence.cvd.<15m\|1h\|4h\|1d>@1` (CVD against price on confirmed swings), `candidate.divergence.oi.<15m\|1h\|4h\|1d>@1` (open interest against price on confirmed swings) | trades; the swing, CVD and 5-minute OI features | yes: the CVD ids from aggTrades; the OI ids at 5-minute OI resolution | yes | Each swing is anchored at the first trade that set its extreme. The archive's 5-minute OI grid point at an anchor can be up to one interval old; an anchor without a ready grid point gives no OI comparison. The location context of each event lists no cluster levels in archive replays (ADR-043) |
| Effort vs result and exhaustion (#22, ADR-051): `candidate.effort_result.<5m\|15m\|1h>@1` (net aggression against displacement, judged against the window's previous 1 440 evaluations), `candidate.exhaustion@1` (aggression decaying at an extreme after a 1h expansion) | trades; the `flow.window.*` and 1m bar features | yes, from aggTrades | yes | Effort vs result warms up over 1 440 evaluations of a window (a day of minutes), exhaustion over six judged 1h evaluations after that. The location context of each event lists no cluster levels in archive replays (ADR-043) |
| Absorption (#22, ADR-051): `candidate.absorption.<5m\|15m\|1h>@1` (effort vs result into replenished passive liquidity within 5 bps) | order book, trades | **no** | **from the start of live depth capture (#10) only** | Live only: built on `book.liquidity.window.*`, so it stays warming up in archive replays; a live run evaluates it only once effort vs result has warmed up (a day of minutes) |
| Bias context (#24, ADR-053): `bias.context@1` (a copy of the 1h volatility regime, and per structure timeframe the step of the last swing pair of each side) | trades; the regime and CVD-divergence features | yes, from aggTrades | yes | Recorded with every trigger and read by no trigger rule. Each component warms up with its input: the regime over 214 closed 1h bars, a timeframe's swing steps from its first anchored swing |
| Auction and SFP triggers (#24, ADR-053): `trigger.failed_auction@1`, `trigger.failed_reclaim@1`, `trigger.breakout_acceptance@1` (on the auction facts of `location.auction.prior_day@1`), `trigger.sfp.<15m\|1h\|4h\|1d>@1` (on the SFP facts of `structure.levels.<tf>@1`) | trades; the auction, structure, location and bias features | yes, from aggTrades | yes | Each trigger is visible at its fact's own event and carries the evidence, a location context at its anchor (the crossed or accepted value edge, or the swept level) and a bias snapshot. The auction trigger values warm up from every UTC-day rollover until the first close under the new prior day. The location context of each event lists no cluster levels in archive replays (ADR-043) |
| Candidate triggers (#24, ADR-053): `trigger.cvd_divergence.<15m\|1h\|4h\|1d>@1`, `trigger.effort_result.<5m\|15m\|1h>@1`, `trigger.exhaustion@1` (on the order-flow candidates of ADR-051, at a defined location) | trades; the candidate, location and bias features | yes, from aggTrades | yes | A candidate is a trigger only if the context the rule reads is ready and lists a level of an admitted kind (`poc`, `vah`, `val`, `hvn`, `lvn`, `structural_high`, `structural_low`, `sfp_zone`, `vwap`). A CVD divergence's gate reads the registry at its current swing without every level of either swing of its pair; the others read the candidate's own context. The gate reads the selected registry and never a cluster level, so it means the same in archive replays and live. Each value warms up with its candidate (the effort ids over 1 440 evaluations) |
| Absorption triggers (#24, ADR-053): `trigger.absorption.<5m\|15m\|1h>@1` (absorption at a defined location) | order book, trades; the candidate, location and bias features | **no** | **from the start of live depth capture (#10) only** | Live only, as its candidate: it stays warming up in archive replays. The gate is that of the other candidate triggers on the candidate's own context: admitted kinds only, never a cluster level |
| OI-expansion triggers (#24, ADR-053): `trigger.oi_expansion_rejection.<15m\|1h\|4h\|1d>@1` (on the SFP of that timeframe) and `trigger.oi_expansion_rejection.prior_day@1` (on the failed auction) | trades, open interest; the structure, auction, OI-grid, location and bias features | yes, from aggTrades and `metrics` | yes | A rejection is a trigger if the `derivatives.oi.5m@1` point at it lies on a later boundary than the point at the excursion's start, with the same resolution and strictly higher open interest. The point at an event is that of the boundary 25 s before it, so the archive (which closes a boundary at itself) and a continuous live feed (which closes it at its first poll after it) select the same boundaries; their values keep their own `resolution_ms`, and no comparison crosses an archive/live seam. An open-interest hole leaves the boundaries it covers without a point. Each value follows its rejection's fact input |
